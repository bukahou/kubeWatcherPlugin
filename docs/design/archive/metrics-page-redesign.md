## 走查发现（浏览器实测 + 源码定位）

页面现状 8 个区块，从上到下：

| # | 区块 | 问题 |
|---|---|---|
| 1 | 标题 + TimeRangePicker | 顶部提示自曝「时间范围仅作用于趋势图」—— 全局选择器管不了大半个页面 |
| 2 | SummaryCard ×4 | 与下方 tiles 同为「当前值快照」，首屏两排 9 张卡全是快照，趋势在第三屏 |
| 3 | HardwareSummaryTiles ×5 | 同上 |
| 4 | 硬件健康矩阵（12列×8行） | ✅ 三个节点视图里最强：有阈值判定 + 设备标注 |
| 5 | 集群资源趋势 ×4 图 | 每张图各带一组 1m/5m/15m 桶按钮（共 4 组）+ 又一组 1h/6h/1d/7d —— 与页面级选择器三方分裂 |
| 6 | **节点对比表（13列×8行）** | 与矩阵 **9 列完全重复**（同数字渲染两遍）；独有 3 列（PSI×2/网络错误）在下钻里都有 |
| 7 | 节点筛选 chips ×9 | 8 节点无筛选必要 |
| 8 | **NodeCard 列表 ×8** | 折叠行 4 数字与矩阵三重复且**无判定**（66.7°C 显示绿色）；展开区是全页唯一下钻（趋势+9 卡）但入口藏在第四屏；nodeIP 字段显示 hostname 导致名字重复两遍 |

### 详情卡的实现层问题（源码已定位）

| 问题 | 位置 | 根因 |
|---|---|---|
| 网络卡列出 lxc*/cilium_* 虚拟接口（Pod 越多越长） | `NetworkCard.tsx:14` | `VIRTUAL_PREFIXES` 停留在旧网络栈时代：有 flannel/calico/docker，**没有 lxc/cilium_**——列表没跟上 Cilium 迁移 |
| 文件描述符显示 `Max: 9223372036854.8M` | `SystemResourcesCard.tsx:17` | int64 max（无限制）无哨兵处理，`fmtN` 直接渲染 |
| 单节点趋势图 CPU%/内存%/磁盘% 与温度°C 画同一 % 轴 | `ResourceChart.tsx` | 混单位单轴（dual-axis 反模式变体）；温度 60°C 被读成 60% |
| CPU 卡内容少于内存卡，大片空白 | NodeCard 布局 | 左右等高网格下内容不均 |
| /boot/firmware 与 / 等权展示 | DiskCard | 静态分区无监控价值 |

## 主流对照（Grafana node-exporter Full / Datadog Host / Lens）

三家共同点，恰好都是本页缺的：

1. **列表轻、详情重**：列表页只做「找到那台不对劲的机器」，点击进独立详情；不在一页塞 8 份手风琴详情
2. **时间控制唯一**：一个页面一个时间范围，图表桶宽自动跟随（1h→15s 桶、7d→5m 桶），不让用户手选采样粒度
3. **虚拟接口默认过滤**：veth/lxc/cni 一律折叠，物理口优先
4. **快照层带判定**：没有「裸数字绿字」——要么有阈值着色，要么不展示

## 方案（C+，已获用户确认方向）

### Phase 1 — 信息架构收拢

```
改后：标题+唯一TimeRangePicker → 快照带(合并瘦身) → 【统一节点表】 → 集群趋势
删除：节点对比表(整块) / NodeCard 列表(整块) / 节点筛选 chips
```

- **统一节点表** = 硬件健康矩阵为基底（保留阈值判定/设备标注），补 `盘用量` 一列
- **行点击 → 展开原 NodeCard 详情体**（资源趋势 + 9 张卡整体搬移，historyCache 逻辑随迁）
- 对比表独有的 PSI/网络错误列不进表——在展开区的 PSICard/NetworkCard 已有
- SummaryCard 与 HardwareTiles 合并为一排（节点、告警、最高温、最慢盘、供电/降频异常——只留有判定语义的，删平均 CPU/内存两张纯快照）

### Phase 2 — 详情卡修缮

- `VIRTUAL_PREFIXES` 补 `lxc`、`cilium_`；虚拟接口默认折叠（「显示 N 个虚拟接口」展开钮），物理口置顶
- 文件描述符 max 为 int64 极值时显示「无限制」，不画进度条
- 单节点趋势图拆双轴或双图：% 系（CPU/内存/磁盘）一图，温度独立
- /boot 类挂载点折叠为一行摘要
- CPU 卡补内容平衡（把负载/PSI-CPU 挪入）或改非等高布局

### Phase 3 — 时间控制统一

- 页面唯一 TimeRangePicker，作用于集群趋势 + 展开区节点趋势
- 桶宽按范围自动推导（映射表），删除 4 组 1m/5m/15m 按钮与 NodeCard 内 1h/6h/24h 按钮
- 顶部那句「时间范围仅作用于趋势图」的免责提示随之删除——设计不需要道歉时就不用道歉

## 验收判据

- 同一个数字在页面上最多出现一次（矩阵行 + 展开详情不算重复：粒度不同）
- 节点从「发现异常」到「看到详情」一次点击
- 全页时间控制点 = 1
- raspi5-one 网络卡默认只显示 eth0
- `go build` + `next build` + 浏览器截图走查复核

## 不做

- 不改后端/Agent（纯前端信息架构重构，数据面不动）
- 不做独立节点详情页路由（8 节点规模行内展开够用，路由化留给多集群时代）
